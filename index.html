  • 안정성 보장 — AI 서버 다운 대비 재시도, 데이터 누락 방지 큐 설계, 로컬 버퍼링

제안 포인트

1. 이기종 PLC 환경 대응 미들웨어 아키텍처

LS PLC는 LSIS Protocol 또는 Modbus TCP, Cimon은 OPC-UA 또는 자체 드라이버, 중국산은 매뉴얼 부재가 흔합니다. 각각의 통신 프로토콜을 추상화하는 PLC 어댑터 계층(Python 기반)을 두고, 상위는 표준 JSON 메시지로만 통신하도록 설계합니다. 매뉴얼이 부족한 PLC는 Wireshark·Modscan 등을 활용한 패킷 캡처·역분석으로 주소맵을 보강합니다. 신규 설비 추가 시 어댑터만 확장하면 되는 구조입니다.

2. Spring Boot ↔ Python 양방향 연계 아키텍처

기존 MES(Spring Boot)는 운영 안정성을 위해 최소 변경 원칙으로 접근합니다. 데이터 적재는 MQTT 브로커를 중심으로 PLC→Python 수집기→PostgreSQL→AI 서버→MES 순으로 단방향 스트림을 구성하고, AI 분석 결과 송신은 REST API + 비동기 큐(예: Redis Stream)로 전송합니다. AI 서버 다운 시에도 데이터 적재는 계속되며, 복구 후 누락분 일괄 재처리됩니다.

3. AI 모델 단계적 고도화 전략

초기에는 FFT Peak + RMS 임계치 규칙 기반으로 빠르게 위험도 판정을 시작하고(데이터 부족 구간 대응), 정상 데이터 누적 후 AutoEncoder 재구성 오차 기반 이상 탐지를 적용, 마지막에 LSTM 시계열 예측으로 고장 사전 예고(Time-to-Failure)까지 확장합니다. 모델별 위험도를 가중 결합하여 오탐을 최소화합니다.

4. 운영 안정성 — 다중 백업 채널

현장 PLC 수집기에 로컬 SQLite 버퍼를 두어 네트워크 단절 시 최대 24시간 데이터 보관, 복구 후 자동 동기화합니다. AI 서버는 헬스체크 기반 자동 재시작, MQTT QoS 1 이상으로 메시지 손실 방지, PostgreSQL은 적재 실패 시 DLQ(Dead Letter Queue)로 격리합니다.

5. 유사 프로젝트 수행 경험 기반 효율적 진행

실시간 데이터 수집·AI 모델 통합·외부 시스템 연동·대시보드 구축을 한 사이클로 수행한 경험이 다수 있습니다(상세는 "유사 프로젝트 경험" 페이지 참조). 검증된 아키텍처 패턴을 활용하여 60일 내 안정적 납품이 가능합니다.

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

화장품 제조공장의 핵심 설비 고장은 돌발적 생산 중단·납기 지연·품질 손실로 직결됩니다. 현재 기존 Spring Boot 기반 MES에서 일부 센서 데이터를 수집 중이나, 본격적인 AI 분석을 위해서는 이기종 PLC(LS·Cimon·중국산) 환경에서의 안정적 데이터 추출과 Python 기반 AI 서버 연계가 필요합니다.

본 프로젝트는 (1) 다양한 PLC에서 온도·전력·진동 데이터를 실시간 수집하고, (2) FFT·AutoEncoder·LSTM 기반 AI 모델로 이상 징후를 사전 탐지하며, (3) 위험도에 따라 MES 팝업·SMS·경광등으로 즉시 알람하는 예지보전 시스템을 구축하는 것을 목적으로 합니다. 정부지원사업 연계 또는 자체 비용으로 2026년 7월 초 착수, 2개월 내 납품을 목표로 합니다.

3. 기능 요구사항

3.1 데이터 수집 및 파이프라인

  • [필수] 이기종 PLC(LS·Cimon·중국산)에서 온도·전력·진동(RMS·Raw) 실시간 수집
  • [필수] PostgreSQL 적재 (TimescaleDB 확장 검토 — 시계열 최적화)
  • [필수] 진동 Raw 데이터 FFT 분석 및 Peak 검출
  • [필수] MQTT 기반 스트리밍 파이프라인, AI 학습 적합 데이터셋 구성
  • [필수] 매뉴얼 부재 PLC 대응 미들웨어 (Wireshark·역분석 도구 활용)

3.2 AI 분석 및 MES 연동

  • [필수] 정상 데이터 기반 AutoEncoder 이상 탐지 모델 학습
  • [필수] LSTM 시계열 예측 모델 (Time-to-Failure 추정)
  • [필수] FFT 규칙 기반 + AI 모델 결합 위험도 판정 (NORMAL/WARNING/DANGER)
  • [필수] AI 분석 결과를 기존 MES로 전송하는 REST API (FastAPI ↔ Spring Boot)
  • [필수] 모델 재학습 파이프라인 (운영 중 정상 데이터 누적 → 재학습)

3.3 알람 시스템

  • [필수] 임계치 초과 시 MES 화면 내 팝업 알람 트리거
  • [필수] 위험도별 SMS 발송 (관리자 그룹별 분기 발송)
  • [필수] 현장 경광등 제어 (Modbus/Relay 인터페이스)
  • [선택] 카카오톡 알림톡 연동 (향후 확장)

3.4 대시보드 (Grafana)

  • [필수] 설비별 실시간 상태 및 위험도 표시
  • [필수] 온도/진동/전력 시계열 트렌드 그래프
  • [필수] FFT 주파수 스펙트럼 시각화
  • [필수] 과거 분석 결과 및 알람 이력 조회 (기간·설비·위험도 필터)

5. 기술 제약사항

  • 레거시 MES 보존 — 기존 Spring Boot MES는 운영 중이므로 최소 변경 원칙 적용. 변경은 REST API 추가에 한정
  • 현장 네트워크 제약 — 공장 내부망 기준 설계, 외부 클라우드 의존 최소화 (필요 시 SMS 게이트웨이만 외부)
  • PLC 매뉴얼 부재 리스크 — 중국산 PLC는 사전 현장 방문으로 통신 가능성 검증 필요
  • 하드웨어 비용 제외 — 본 견적은 순수 소프트웨어 개발(파이프라인·AI·연동·대시보드) 기준이며, 센서·PLC 모듈·경광등 등 하드웨어 비용은 별도
  • 현장 출장 범위 — 서울·오산·부천 등 1시간 30분 이내 거리 기준, 추가 권역은 별도 협의

6. 범위 외 사항 (Out of Scope)

  • 센서·PLC·경광등·SMS 게이트웨이 등 하드웨어 구매 및 설치
  • 기존 MES 화면(Spring Boot 측 프론트엔드) 신규 개발 — 클라이언트 측 JAVA 개발자 2명 담당
  • 설비 도면·매뉴얼·주소맵의 신규 작성 (기존 보유 자료 활용)
  • 운영자 교육 프로그램 (운영 매뉴얼 제공으로 갈음)
  • 화장품 제조 공정 자체의 컨설팅
